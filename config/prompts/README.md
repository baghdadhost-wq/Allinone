# قوالب الواجهة الرسومية

| الملف | متى يُستخدم | المتغيرات |
|---|---|---|
| `deep_thinking.txt` | عند تفعيل «التفكير بعمق» | `[ينقل السؤال هنا]` يُستبدل بسؤالك |
| `memory.txt` | عند تفعيل Memory | `{transcript}` نص المحادثة · `{file}` مسار ملف txt · `{message}` رسالتك |
| `report_header.txt` | أعلى ملف «تقرير الأخطاء» 🧾 (ما يُطلب من النموذج الأذكى) | — |
| `report_request.txt` | الرسالة الجاهزة عند «إرسال التقرير إلى نموذج آخر» | — |
| `continue.txt` | رسالة «▶ متابعة» بعد انقطاع العمل | `{reason}` سبب الانقطاع |
| `handoff.txt` | المتابعة في جلسة جديدة أو على بوابة أخرى | `{handoff}` ملف التسليم · `{file}` مساره · `{reason}` · `{message}` |
| `work_method.txt` | طريقة العمل التي تُرسل مع كل تشغيل عند تفعيل «🔁 تحقق وأصلح» | — |
| `verify_fix.txt` | ما يُعاد إلى النموذج عند فشل التحقق الآلي | `{cmd}` `{code}` `{round}` `{max}` `{output}` |
| `verify_change_approach.txt` | يُضاف عند تكرر الخطأ نفسه (تغيير الأسلوب) | — |
| `verify_self_check.txt` | عند عدم وجود أمر تحقق: يُطلب من النموذج أن يجرّب بنفسه مرة | — |
| `visual_method.txt` | عند تفعيل «👁 تجربة فعلية»: كيف يجرّب النموذج البرنامج بأدوات المتصفح | — |
| `visual_review.txt` | ما يُطلب من النموذج الذي يرى الصور عند مراجعة اللقطات | `{request}` `{shots}` `{problems}` |
| `visual_fix.txt` | ما يُعاد إلى النموذج إذا ظهرت مشاكل في التجربة الفعلية | `{command}` `{url}` `{count}` `{dir}` `{problems}` `{shots}` `{round}` `{max}` |
| `bridge_request.txt` | طلب «🌐 Claude.ai يدوي»: كيف يكتب Claude ردّه + المشروع والملفات | `{project}` `{instructions}` `{handoff}` `{tree}` `{files}` `{checks}` `{request}` |
| `run_rules.txt` | قواعد تُرسل مع كل تشغيل (الخوادم في الخلفية، مخرجات قصيرة) | — |
| `expert_answer.txt` | عند «رفع إجابة» 📥 إلى المحادثة | `{answer}` الإجابة المرفوعة · `{note}` ملاحظتك |

عدّل النص كما تريد، ويُطبَّق التعديل على الرسالة التالية مباشرة دون إعادة تشغيل.
يرى المستخدم سؤاله فقط، والنص الكامل يظهر عند تفعيل «إظهار ما يحدث فعلياً».
